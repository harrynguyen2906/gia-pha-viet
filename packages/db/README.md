# @gia-pha/db — Shared Database Package

This is the **single source of truth** for the Heritage Cloud (Gia Phả Việt) database.

All schemas, migrations, and seed data live here. Every app shares this database.

---

## 📁 Structure

```
packages/db/
├── prisma/
│   ├── schema.prisma       ← MASTER schema (public + admin schemas)
│   ├── migrations/         ← All database migrations
│   └── seed/
│       ├── index.ts        ← Run all seeds together
│       ├── seed-public.ts  ← Clan, members, rituals, duties, grave sites
│       └── seed-admin.ts   ← Subscription tiers, admin users
├── src/
│   ├── client.ts           ← Singleton PrismaClient
│   ├── index.ts            ← Public exports
│   └── generated/          ← Auto-generated by `npm run db:generate` (do not edit)
├── prisma.config.ts        ← Prisma config (schema path, migration path, seed)
├── package.json
└── .env.example            ← Copy to .env.local and fill in credentials
```

---

## ⚙️ Setup

### 1. Create your `.env.local`

```bash
cp .env.example .env.local
# Then edit .env.local with your Supabase credentials
```

Required variables:
```env
# Runtime connection (via pgBouncer / connection pooler)
DATABASE_URL="postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres?pgbouncer=true"

# Direct connection for migrations (bypasses pgBouncer)
DIRECT_URL="postgresql://postgres:[password]@db.[ref].supabase.co:5432/postgres"
```

### 2. Install dependencies

```bash
npm install
```

### 3. Generate the Prisma client

```bash
npm run db:generate
```

## 📜 Available Scripts

| Command                    | What it does                                        |
|----------------------------|-----------------------------------------------------|
| `npm run db:generate`      | Regenerate Prisma client from schema                |
| `npm run db:migrate:dev`   | Create a new migration (development)                |
| `npm run db:migrate:deploy`| Apply pending migrations (production/Supabase)      |
| `npm run db:migrate:status`| Check which migrations have been applied            |
| `npm run db:seed`          | Seed ALL data (public + admin)                      |
| `npm run db:seed:public`   | Seed public schema only (clan, members, rituals...) |
| `npm run db:seed:admin`    | Seed admin schema only (tiers, admin users)         |
| `npm run db:studio`        | Open Prisma Studio (visual DB browser)              |
| `npm run db:reset`         | ⚠️ Reset DB and re-run all migrations (dev only!)   |
| `npm run db:validate`      | Validate the schema file                            |
| `npm run db:format`        | Auto-format the schema file                         |

## 🔄 Workflow: Making a Schema Change

> **Always do this from `packages/db`, never from an individual app.**

```bash
# 1. Edit prisma/schema.prisma

# 2. Create a migration
npm run db:migrate:dev
# → Prisma will ask for a migration name, e.g. "add_member_nickname"

# 3. Regenerate the client
npm run db:generate

# 4. Deploy to production (or Supabase)
npm run db:migrate:deploy
```

## 🌱 Seeding

```bash
# Seed everything at once
npm run db:seed

# Only seed public data (clans, members, rituals, etc.)
npm run db:seed:public

# Only seed admin data (subscription tiers, admin user)
npm run db:seed:admin
```

## 🏗️ How Apps Use This Package

Each app (`gia-pha-web`, `gia-pha-admin`, future `gia-pha-app`) continues to:
- Keep its own `prisma/schema.prisma` (synced/aligned with this master)
- Run its own `prisma generate` via `postinstall`
- Import from its own `src/generated/prisma` or `src/lib/prisma`

This `packages/db` package is the **operational hub** — you run all migration and seeding commands from here. No more confusion about which app folder to run migrations from.

---

## ⚠️ Important Rules

1. **Only run `prisma migrate` from this folder**, never from `gia-pha-web` or `gia-pha-admin`.
2. **After any schema change here**, manually sync the change to the relevant app's `prisma/schema.prisma` too, then run `npm run postinstall` (or `prisma generate`) in that app.
3. **Never commit `.env` or `.env.local`** — they contain database passwords.
4. **`src/generated/`** is auto-generated — never edit it manually.
